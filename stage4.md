4. Notable Implementation Anomalies in the Data Layer
Array Storage for Singular Scalar References [Confirmed]:
Profile.userId, ClientModel.userId, and InvoiceModel.creator are defined as [String] (arrays of strings) in server/models/ProfileModel.js:12, server/models/ClientModel.js:9, and server/models/InvoiceModel.js:15.
In queries, controllers execute direct equality queries ({ creator: searchQuery } or { userId: searchQuery }), relying on MongoDB's multi-key array index unwrapping.
Static Schema Default Execution Bug [Confirmed]:
Both ClientModel.createdAt (server/models/ClientModel.js:12) and InvoiceModel.createdAt (server/models/InvoiceModel.js:21) define default: new Date() instead of passing the function reference default: Date.now.
Result: new Date() is evaluated once when Node.js parses the file on startup, meaning any documents saved without an explicit createdAt receive the server's boot timestamp.
No Schema Validation on Financial Fields [Confirmed]:
In InvoiceModel, total, subTotal, vat, rates, and line items do not enforce min/max constraints, required flags, or non-negative checks at the database layer (server/models/InvoiceModel.js:6–10). Calculations are performed purely on the client side before dispatching createInvoice / updateInvoice (client/src/components/Invoice/Invoice.js:167–197, 233–250).
